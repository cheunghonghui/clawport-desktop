# ClawPort Desktop 云端账号登录

## 目标与边界

桌面本地运行 Harness，浏览器登录 ClawPort 并确认设备授权。主进程保管凭据，原生设置面板展示账号、律所、设备和登录状态。现有会话、导入数据及云端容器保持不变。

本阶段实现设备授权、设备持久身份、续期、撤销和身份 bootstrap。业务插件访问与模型凭据下发属于后续阶段；设备令牌不直接充当浏览器身份。

## Task 1: 云端设备授权服务

新增独立的设备授权、设备、会话数据模型及迁移。浏览器使用现有账号鉴权确认，桌面使用独立不透明令牌。授权码只能兑换一次；刷新令牌轮换；注销与成员停用立即失效。同一安装重新授权保持设备和本地运行标识。

验证未批准、拒绝、过期、并发兑换、并发刷新、撤销、跨成员隔离及重新授权。使用隔离测试数据库，测试服务器上的现有业务数据不参与清理或迁移测试。

## Task 2: 桌面账号服务与原生设置入口

主进程维护授权轮询、续期、离线恢复、凭据保管和状态事件。系统安全存储仅保存加密刷新令牌，访问令牌只保存在内存。通过具名 IPC 暴露非敏感状态；校验调用窗口与主 frame。

在现有宿主插件设置 slot 展示中英文账号状态、登录、重试与退出。授权使用系统浏览器；断网保留可恢复凭据；注销取消未完成流程；重复点击不重复启动授权。

## Task 3: 浏览器确认与受限代理

提供独立设备确认页，通过已有账号登录和工作区选择完成批准或拒绝。公共设备代理只开放设备申请、轮询、续期、bootstrap、注销，不转发浏览器 Cookie 或任意租户头。

验证代理方法与路径限制、登录返回地址、工作区选择、错误反馈、批准/拒绝和敏感令牌不进入页面。

## Task 4: 集成验收

串联真实 PostgreSQL、控制 API、Web 代理和桌面主进程。验证重启续期、身份保持、撤销与失效。桌面以独立开发 Profile 验证原生设置 UI，保留现有已运行窗口和用户导入数据。

桌面执行相关测试、typecheck、build 和完整测试，测试并发最多为 2。平台执行本次相关测试及类型检查。完成代码审阅和验证记录后提交桌面分支；云端发布另行安排。
